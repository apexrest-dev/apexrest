# Current changes

## Unreleased

- Redesign the README and the documentation: a task-oriented documentation hub, a features page with an overview table, regrouped site navigation and a guide to how `build webapp` works. Remove the video series from the documentation.
- Add `apexrest build webapp`: a standalone Node.js application for an APEXlang application that renders the pages with Universal Theme and runs their SQL and PL/SQL in an existing Oracle database through `node-oracledb`, with real sign-in, login-required pages and enforced authorization. A first version: session state protection is not implemented and one process serves one request at a time. See [build a web application](docs/webapp.md).
- Word errors with the application's error handling function in a built web application and the connected preview: an error that carries an ORA code is passed to the function in Oracle (needs the APEX error API in the database) and its message replaces the database error stack.
- Load the interactive grid model once: a page with a popup LOV and an interactive grid loaded Oracle's model script twice and raised a JavaScript error on load.
- Apply item defaults to a new form row in the preview: form initialization cleared them.
- Draw map layers whose geometry column is an Oracle `SDO_GEOMETRY` in a built web application (points, straight-edged lines and polygons, rectangles and their multi forms), and treat a layer without `geometryColumnDataType` as SDO_GEOMETRY, the APEX default, unless it maps longitude/latitude or GeoJSON columns.
- Fix the unit-aware capacity summary pattern recipe: its report query used the Oracle reserved word `RESOURCE` as a column alias and failed with ORA-00923; the column is now `RESOURCE_NAME`.
- Run the application's database code in the local preview: packages (specification, body, package variables, initialization, overloads), standalone functions and procedures and anonymous blocks of the install scripts, called from PL/SQL and from SQL; BEFORE row triggers that fill keys and audit columns; supporting-object install scripts in their declared order; and Oracle-only install statements skipped or translated instead of failing. See [local preview](docs/local-preview.md#application-database-code).
- Run region and item plug-ins written in PL/SQL in the local preview: render and ajax callbacks, custom attributes, `apex_plugin_util.get_data2`, `apex_javascript`, `apex_css`, `apex_json` and the plug-in's own files.
- Translate more Oracle SQL locally: `(+)` outer joins, hierarchical queries in every statement, `#OWNER#`, `sys.` prefixes, `SELECT UNIQUE`, interval literals, `ora_hash`, `numtodsinterval`; add Oracle dictionary views (`USER_TABLES`, `USER_SOURCE`, `ALL_OBJECTS`, …) and APEX `SOURCE_TYPE` values in the APEX dictionary.
- Add `npm run preview:corpus`, which renders every page of Oracle's 33 public APEX 26.2 applications in the preview and counts what it cannot run. On that corpus, pages that failed to render went from 20 to 0, plug-in placeholders from 249 to 2 and application package calls not run from 3,066 to 30.

## 2.7.0

- Deploy a changed application in about half the time. On a local APEX 26.2 database with SQLcl 26.3, adding one page through `apexrest_apex_validate` and `apexrest_ship mode:apply` (full import) took 23.8 s instead of 51.4 s at 7-9 pages and 28.7 s instead of 56.6 s at 23-28 pages. The identity checks, the three exports, the backup, the SQLcl restriction level and the outcome classification are unchanged. See [architecture](docs/architecture.md#persistent-sqlcl-engine).
  - The reads of one plan or one apply share one connected SQLcl server instead of starting a process each (`APEXREST_CONNECTED_READS=0` restores one process per read).
  - A full APEXlang import runs on a restricted server (`-R 2 -mcp`) that loaded the compiler while the target was backed up; each start checks that SQLcl refuses `HOST` in server mode and otherwise the ordinary import process runs (`APEXREST_WARM_IMPORT=0` disables it).
  - SQLcl capabilities are kept for one day in the managed home, so a deployment worker does not start two JVMs to read them (`APEXREST_CAPABILITY_CACHE=0` disables the file).
- Keep the completion marker of a SQLcl server batch on its own line: SQLcl 26.3 can end JSON output without a newline.
- Align package, workspace and Codex/Claude Code source versions to 2.7.0. Registry distribution and full native/Oracle qualification remain separate outcomes.

## 2.6.0

- Report source the local preview never runs: `apexrest_preview` `start`, `check` and `status` return initialization JavaScript functions (`componentAdvanced` or `advanced.initJavaScriptFunction`, both accepted by the compiler and run by APEX) as `notAppliedLocally`; chart and calendar diagnostics for them are warnings, and a chart with one shows a visible note in the preview page. The work skill tells the agent to check such code in APEX.
- Fix `apexrest_reference mode:select` failing with `INTERNAL_ERROR` when an over-budget result page held results that carry an example and no summary text.
- Add the [field report](docs/apex-design-race.md) comparing the same APEX application built with and without the plugin, including a browser design check, with screenshots and a timeline.
- Align package, workspace and Codex/Claude Code source versions to 2.6.0. Registry distribution and full native/Oracle qualification remain separate outcomes.
- Mention entry skeletons in the work skill.
- Explain a `DUPLICATED_COMPONENT` error for processes without an `executionMappingIdentifier`: the hint now says to give every process of the page its own `advanced { executionMappingIdentifier }`.
- Outline breadcrumb and list entries in 26.2 component selection: the Oracle sample pages hold no shared components, so a selected entry contract carries a `skeleton` with each always-applicable property in its group (`parentEntry` inside `appearance` for a breadcrumb entry, inside `layout` for a list entry) and its value type or values. `select` returns 16 results by default, so buttons, processes and entries fit a long request.
- Point the work skill at the new selection and repair data: name every component by its APEX name in `select`, adapt `example` blocks and `pageExamples` directly, apply a `Fix:` hint without lookups, and leave SQLcl and connection checks to the tools.
- Return compiler diagnostics (more than five) and `metadata_read` results inline up to 32 KB instead of compacting them to an artifact above 8 KB, so a first validation of new pages arrives as one complete repair list.
- Add repair hints from the 26.2 property contracts to `INVALID_PROPERTY` compiler diagnostics: the `hint` ends with `Fix:` and says where the property belongs (`parentEntry belongs in group appearance of entry`), when it applies (`onValue applies to pageItem (type: switch) only when settings.useDefaults = N`) or which properties the group accepts.
- Return working APEXlang with 26.2 component selection: each selected page component carries `example`, a block from an Oracle 26.2 sample page of the same kind (region, page item, button, process) that prefers the variant the request names (a line chart, not a pie), and a modal form request adds `pageExamples` with one whole sample page (create/save/delete buttons, cancel action, initialization, row processing, close dialog). Components the request names (switch, select list, button, PL/SQL process, list and breadcrumb entries) now reach the Decisions shortlist ahead of regions that only share vocabulary; `select` returns up to 12 results by default (16 at most), and results with an example omit their routing summary and links.
- Install the local preview assets on first use: `preview` runs the asset setup itself when the APEX assets are missing and reports `PREVIEW_ASSETS_MISSING` only when that setup fails.
- Accept the ship wait limit of up to 120 seconds in `apexrest_ship mode:recover`; it previously rejected `waitSeconds` above 30.
- Keep the plain facts of a failure in the result: strings, numbers, booleans and short lists from the fault details (such as `deploymentRunId`, `expectedAlias` and `usedBy`) now reach `data`, redacted. Previously a failed result dropped every detail, so `mode:recover` had no deployment run ID to work with.
- Detect an application alias that another application of the workspace already uses while planning, as `APPLICATION_ALIAS_IN_USE` with the alias and the applications using it, instead of after an import: APEX imported such an application with a suffixed alias and the post-deploy identity check then rejected it. The identity failure names the observed and expected alias and the `deploymentRunId`, and `mode:recover` with an unknown run reports `DEPLOYMENT_RUN_NOT_FOUND`.
- Refuse a connected preview whose SQLcl saved connection autocommits: the preview checks that ROLLBACK works before the first query and otherwise reports `PREVIEW_AUTOCOMMIT_ON` with the `ojdbc.properties` file of that connection to which `autoCommit=false` must be added. Saved connections autocommit by default in SQLcl 26.1 and 26.3, so every preview statement committed and the rollback failed with ORA-17274.
- Run npm-installed peer review CLIs on Windows: `codex.cmd` and `claude.cmd` shims are read and their Node script started directly, so the inline JSON schema never passes through cmd.exe, and native `.exe` installs run as they are. The CLI is looked up only on absolute `PATH` entries, so a `codex.exe` or `claude.exe` in the project folder is never run. Previously a peer CLI installed with npm was always reported unavailable on Windows.
- Let `apex sync --action init` accept a freshly generated application that Oracle rewrote on import: when the only differences from the server export are `deployments/default.json` gaining the configured `app.id` and an empty deinstall script with its reference being dropped, init adopts the server bytes for those files and reports them in `normalized`. Any other difference still fails with `SYNC_SOURCE_CONFLICT`, and nothing is changed. Previously `project init --template blank-app`, a first `ship` and `apex sync --action init` always conflicted.
- Push live updates to local preview pages over a WebSocket (`<app>/__apex/live`). Writes to local tables refresh the regions that read them in every tab and session. `.apx` edits reload open pages, and parse errors appear on the page. The toolbar's Live button shows presence. Grids with unsaved edits and forms are never refreshed, and refresh loops are prevented. Connected mode pushes only source reloads.
- Check preview properties against the component type the compiler uses. Report columns, dynamic action actions, display conditions, grid column settings, required slots and sequences are now checked. The generated showcase application had 173 distinct compiler errors and no preview warnings; `preview check` now reports 161 of them. Oracle's 1,350 public sample pages still produce no findings.
- Make CLI previews discoverable and stoppable across processes: `preview status|stop` accept `--project`, `--source-dir` and `--port`. A stop that stops nothing reports `PREVIEW_NOT_RUNNING`. Add `apex validate --source-dir`, per-command `--help` and bare boolean flags, and remove the unsupported `sandbox` stub.
- Refuse production-marked environments before any connection or SQLcl call in plan, apply and restore. Report a missing SQLcl saved connection as `SQLCL_CONNECTION_NOT_FOUND`. Keep component recipes and patterns in reference searches scoped by a project. Explain composer compiler mismatches with the matching blueprints. Warm up connected previews before the URL is returned.
- Fix local preview chart text in dark theme styles, the grid Color editor rewriting values that were not edited, a grid null error after a save, and toolbar times (now local) and counts (now pluralized). Truncated compiler reports now say where the full diagnostic list is.
- Add `productionDatabases` to `$APEXREST_HOME/production-trust.json`: listing a `DB_UNIQUE_NAME` makes every service name, workspace, schema and application on that database production, so a production mark no longer depends on the service name or application ID a project configures.
- Bind peer reviews to the real plan: the saved plan must match its digest and pass apply's local checks before the reviewer runs, `required` mode refuses and ignores reviews by the host agent's own vendor, and the agent's `focus` text is fenced as an untrusted request in the reviewer prompt.
- Give SQLcl write sessions (imports, migrations, packages, restores) up to 60 minutes instead of the 3-minute read limit, and do not recover or re-import automatically after APEXREST stopped SQLcl on a timeout, cancellation, output limit or unconfirmed batch: the server may still be executing the call. Lost responses and Oracle errors keep the server-first automatic recovery.
- Run dynamic action server code in the local preview only as the application defines it. Rendering a page registers each Execute Server-side Code and SQL/PL/SQL Set Value action in the session; the browser sends only its reference, and the routes ignore any code, SQL or type in the request. Only the declared Items to Submit are set and only the declared Items to Return come back. The registered code is the source as written, without `&ITEM.` substitution, as in APEX. Previously the preview executed whatever code a request contained.
- Read comments, string literals, q-quotes and quoted identifiers in one pass, as Oracle does, before checking connected preview code for COMMIT, ROLLBACK, EXECUTE IMMEDIATE, DBMS_SQL and autonomous transactions. Previously a `q'[` inside a comment hid a following `COMMIT`; code with an unclosed literal or comment is now refused.
- Keep APEX built-ins such as `APP_USER`, `APP_ID`, `APP_SESSION`, `APP_PAGE_ID` and `REQUEST` out of reach of session state in the local preview: URL parameters with those names are ignored with a warning, and binds, `&NAME.` substitutions, the PL/SQL interpreter, `v()`, `nv()` and `apex_util.get_session_state` always return the engine value. Previously `?app_user=ADMIN` changed `:APP_USER` in every query, condition and authorization check, also in connected mode.
- Stop connected preview code from leaving its SQLcl block: page code and region SQL with a line SQLcl acts on regardless of quoting (only `/`, only `.`, a leading `#`, or in SQL a line ending with `;`) are refused before anything is sent, and bind values reach the script without raw line breaks. Previously such code could end its `begin…end;` early and run DDL, which commits.
- Refuse local preview requests that another web page could send: a `Host` other than the preview's loopback address and port, an unsafe method with a foreign or `null` `Origin`, and cross-site or same-site requests other than top-level GET navigations. Previously any page in the browser could post SQL or PL/SQL to the preview, which in connected mode runs against the DEV/QA/TEST database.
- Require a per-run completion marker after every migration and package script. A script whose output lacks it (an early exit, or a client command such as ACCEPT that consumes the remaining input) leaves the migration `started` with an unknown outcome instead of recording it as succeeded or applied.
