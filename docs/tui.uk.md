# Термінальний інтерфейс

[English](tui.md) | Українська

Дія налаштувань SQLcl також вибирає **Direct Oracle listener / ORDS HTTP(S)** для нових операцій. Облікові дані ORDS задаються в локальній панелі або через CLI `connection add --password-file`; список збережених з’єднань SQLcl стосується прямого доступу. Див. [налаштування ORDS](ords.uk.md).

Запустіть `apexrest` або `apexrest tui` в інтерактивному терміналі. Головний екран показує логотип APEXREST, панель APEXlang і сім дій без меню категорій:

| Дія                          | Поведінка                                                                                                                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install tools                | Встановлення керованих Node.js, Java, SQLcl та браузерних інструментів.                                                                                                                       |
| Uninstall tools              | Видалення записаних керованих версій. Зовнішні середовища виконання, проєкти, збережені з’єднання й кеш завантажень зберігаються. Node.js, потрібний засобу запуску або плагіну, залишається. |
| Install plugin               | Встановлення плагіна APEXREST для Codex із наявним середовищем виконання. Інструменти встановлюються окремою дією.                                                                            |
| Uninstall plugin             | Видалення керованої реєстрації плагіна Codex та файлів плагіна; спільні інструменти зберігаються.                                                                                             |
| List saved SQLcl connections | Читання локального сховища SQLcl і показ списку з пошуком.                                                                                                                                    |
| Test saved SQLcl connection  | Відкриття списку з’єднань; Enter перевіряє вибране з’єднання й читає ідентичність бази даних.                                                                                                 |
| SQLcl mode: CLI / MCP | Вибрати SQLcl CLI або офіційний SQLcl MCP для нових Oracle-операцій. |

Створення проєктів, розгортання, тести, повний пошук довідкових документів, діагностика й інші робочі дії залишаються доступними через явні CLI-команди та плагін Codex. У цьому TUI їх немає. Застарілий аргумент `tui --project PATH` приймається для сумісності; ці сім дій не використовують проєкт.

[Почніть зі встановлення через термінал](getting-started.uk.md#встановлення-через-термінал), якщо `apexrest` ще не налаштовано. **Install plugin** створює керований засіб запуску; саме встановлення інструментів його не створює.

## Панель APEXlang

На головному екрані також є таблиця підтримуваних елементів і компонентів APEXlang. Поточний комплект Oracle `26.1@b94ccf4` охоплює **99 типів у 9 групах**, зокрема **23 елементи сторінки**. Групи: елементи сторінки, регіони, кнопки, бізнес-логіка, спільні компоненти, шаблонні компоненти, макети сторінок, приклади сторінок і компоненти робочого простору. Назви та кількість документів беруться з локального комплекту довідників; мережа, SQLcl і з’єднання з базою не потрібні.

Натисніть **Tab**, щоб перейти від дій до каталогу. Введіть назву або групу, наприклад `select-list`, `chart` чи `shared components`. Up/Down, Page Up/Page Down та Home/End переміщують вибір. Enter у каталозі нічого не запускає. Esc очищає пошук або повертає фокус до дій; Tab перемикає панелі, зберігаючи обидва пошуки. Ctrl+R повторно читає локальний каталог, якщо він недоступний.

Стовпець **Docs** рахує комплектні шаблони, контракти та посібники для відповідного типу. Каталог показує довідкове покриття, а не результат компіляції всіх варіантів на вашій цілі: перевіряйте створений код установленим компілятором. Широкий термінал показує дії й таблицю поруч; звичайний — таблицю під діями, а після Tab розгортає її. Менші екрани використовують компактний список із прокручуванням.

## Режим SQLcl: CLI або MCP

Відкрийте **SQLcl mode: CLI / MCP**, виберіть `cli` або `mcp`, перегляньте налаштування й натисніть Enter для збереження. Головний екран показує збережений режим. Для наявних інсталяцій типовим залишається CLI. Приватне налаштування зберігається у `$APEXREST_HOME/sqlcl.json` (зазвичай `~/.apexrest/sqlcl.json`) і діє для нових Oracle-операцій із CLI та APEXREST Codex MCP. Поточні операції зберігають свій режим. Для оновленого runtime перевстановлення не потрібне. Старішу встановлену версію плагіна потрібно оновити, щоб вона читала це налаштування.

- `cli` запускає виконуваний файл SQLcl безпосередньо через наявний механізм із лімітами процесу.
- `mcp` запускає **офіційний Oracle SQLcl MCP** командою `sql -mcp`, визначає його інструменти, за потреби підключається за точною збереженою назвою та виконує пакет SQLcl-команд через `sqlcl_run` або підтримувану старішу назву. Кожна сесія має власний сервер і з’єднання. Невдала MCP-команда не повторюється через CLI.

```sh
apexrest sqlcl status --json
apexrest sqlcl configure --mode cli --json
apexrest sqlcl configure --mode mcp --json
```

**Advanced options → MCP restrict level** типово має значення `4`, тобто стандартні обмеження Oracle MCP. Цей режим використовується для читання, списку збережених з’єднань, експорту й офлайн-валідації. Для запису потрібна зупинка скрипта після помилки, недоступна на рівні 4; deploy apply відхиляє таке налаштування до отримання права виконання й запису. Явно виберіть `1` для дозволених імпортів і скриптів: цей рівень дозволяє скрипти, але блокує команди хоста. Вибір режиму чи рівня обмежень не надає дозволу на запис у БД. Чинні перевірки довіри до проєкту, ідентичності цілі, плану, резервної копії та дозволу залишаються обов’язковими.

```sh
apexrest sqlcl configure --mode mcp --mcp-restrict-level 1 --json
```

Помилка транспорту, тайм-аут, скасування чи неповне підтвердження після відправлення запису залишають результат невідомим і потребують звіряння. Клієнт опитує повернутий ID фонової операції замість повторного запуску команди; невідомий формат статусу спричиняє помилку. MCP-режим не реєструє другого сервера в Codex. Oracle MCP може записувати власний `DBTOOLS$MCP_LOG` під час операцій із підключенням, тому читання даних застосунку не гарантує відсутності всіх записів у БД. Див. [Oracle MCP](https://docs.oracle.com/en/database/oracle/sql-developer-command-line/26.1/sqcug/sqlcl-mcp-server.html) і [рівні обмежень](https://docs.oracle.com/en/database/oracle/sql-developer-command-line/25.3/sqcug/configuring-restrict-levels-sqlcl-mcp-server.html).

## Збережені з’єднання

Список читає назви через SQLcl `connmgr list -flat`. Псевдонім APEXREST не потрібен, облікові дані не експортуються. Вводьте текст для фільтрації, вибирайте стрілками Up/Down і натискайте Enter для перевірки. Ctrl+R оновлює список; Esc очищає фільтр або повертає до меню. Обидві дії з’єднань відкривають цей список.

Перевірка передає точну збережену назву параметру SQLcl CLI `-name` або інструмент MCP `connect` і виконує запит ідентичності бази даних лише для читання. Результат показує базу, сервіс і схему або фактичну помилку. З’єднання має містити чинні облікові дані; відсутні дані налаштовуються в SQLcl. Поля пароля в TUI немає. Для порожнього сховища пояснено, що з’єднання спершу треба зберегти в SQLcl. Див. [документацію менеджера з’єднань Oracle](https://docs.oracle.com/en/database/oracle/sql-developer-command-line/26.1/sqcug/connmgr.html).

Відповідні CLI-команди:

```sh
apexrest connection list --saved --json
apexrest connection test 'Development connection' --saved --json
```

Без `--saved` CLI й надалі використовує локальні посилання APEXREST на з’єднання.

## Встановлення й видалення

У TUI немає перемикачів **Preview only** і **Approve changes**. Налаштуйте потрібні параметри, відкрийте перегляд і натисніть Enter, щоб одразу встановити або видалити вибране. Остаточне натискання Enter є технічним дозволом (`yes=true`, `dryRun=false`); вихід із перегляду нічого не виконує. Встановлення плагіна й видалення інструментів відкривають перегляд одразу; Esc повертає до параметрів. Згода з ліцензією Oracle та дозвіл системних пакетів залишаються окремими й типово вимкнені; посилання на умови Oracle показано на екрані перегляду інструментів. Ctrl+O розгортає додаткові параметри. CLI `--dry-run` залишається доступним; він показує наявний інструмент як `found, not probed`, не запускаючи його.

Видалення інструментів прибирає лише записану версію всередині керованого каталогу. Воно відхиляє символічні посилання в батьківських керованих каталогах і координується з керованим встановленням. Node.js залишається, якщо він потрібен поточному процесу, керованому засобу запуску або запису встановлення. Системні пакети й сховище з’єднань SQLcl не видаляються.

```sh
apexrest dependencies uninstall --dry-run --json
apexrest dependencies uninstall --yes --json
```

Якщо видаляєте інструменти й плагін, спершу видаліть інструменти. Видалення файлів плагіна прибирає код керованого засобу запуску; **Keep plugin files** зберігає цей код після скасування реєстрації. Команда Node з копії репозиторію залишається доступною. Див. [повний посібник видалення](getting-started.uk.md#видалення-керованих-інструментів-і-плагіна).

## Клавіші

| Екран     | Керування                                                                                                              |
| --------- | ---------------------------------------------------------------------------------------------------------------------- |
| Головний  | Tab перемикає дії/каталог; Up/Down вибирає; Enter відкриває дію; введення шукає; Esc очищає пошук або повертає назад/виходить.                                       |
| Форма     | Up/Down або Tab вибирає; Enter редагує чи перемикає; Ctrl+O розгортає додаткові параметри; Ctrl+R відкриває перегляд.  |
| Редактор  | Left/Right/Home/End переміщує; Backspace/Delete видаляє; Ctrl+U очищає; Enter зберігає; Esc скасовує редагування.      |
| Перегляд  | Enter виконує; Esc повертає до редагування; D показує деталі команди.                                                  |
| З’єднання | Введення фільтрує; Enter перевіряє; Ctrl+R оновлює; Esc очищає фільтр або повертає назад.                              |
| Результат | D перемикає JSON; Up/Down та Page Up/Page Down прокручують; Enter повертає до форми чи з’єднань; Esc повертає до меню. |

Ctrl+C виходить, коли операція не виконується. Під час виконання він запитує скасування й очікує фактичного результату. Вихід відновлює звичайний екран, курсор і режим введення. Мінімальний розмір термінала — 30 стовпців на 10 рядків; `NO_COLOR` вимикає кольори. Запуск без аргументів через канал або з `TERM=dumb` друкує довідку; явний `tui` потребує інтерактивного введення й виведення.

## Запуск і перевірка

У копії репозиторію виконайте `node plugins/apexrest-apex/runtime/apexrest.mjs`. Після змін перебудуйте пакет через `npm run plugin:sync`. Локальний засіб запуску для розробки вказує на це середовище виконання; зміни консолі не потребують нативного перевстановлення. Налаштування PATH описано в [посібнику встановлення](getting-started.uk.md#використання-cli).

[Докази прямого виконання](evidence/tui-direct-run-local.json) перевіряють застосування після Enter без перемикачів попереднього перегляду або дозволу; видалення виконано лише для тимчасової фікстури інструмента. [Попередні докази скороченого TUI](evidence/tui-focused-local.json) відокремлюють автоматизовані фікстури, фактичний запуск у терміналі Linux і локальне читання списку SQLcl. Відповіді перевірки SQLcl у термінальних тестах є явними фікстурами, а не успішними з’єднаннями Oracle. Локальне сховище було порожнім, тому реальну перевірку з’єднання з базою не виконано. Перевірки терміналів macOS/Windows залишаються відкритими. Попередні докази TUI описують попередні меню.

[Перевірка панелі APEXlang](evidence/tui-apexlang-dashboard-local.json) фіксує перевірки покриття каталогу, навігації та розмірів термінала. Це локальні перевірки TUI, а не докази компіляції Oracle чи нативної реєстрації Codex.
