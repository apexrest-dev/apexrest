    Fast-development follow-up backlog (2026-11-25, local, branch feat/fast-development)

    Work items are APE-405 to APE-438 in Linear; each section names its backlog ID. Implementation, repository tests, compiler evidence, native import and browser observations are reported separately.

    A01 compound page edits (APE-405). packages/core/src/edit/transaction.ts plans every operation of one request against one immutable page snapshot, combines the text edits, parses the result, has each operation read its change back and only then replaces the file atomically under the source-edit lock after rechecking the digest. project action:edit (project.edit) accepts set operations (the patch properties and query) and insert fragments in one request. patch and insert now run through the same transaction with unchanged results. Operations target only components of the snapshot read. Verified by tests/unit/source-edit-transaction.test.ts (combined write, byte-identical failures, stale digest, MCP routing) and the existing patch and insert tests. No compiler or native import run is claimed for this change.

    A02 context after every edit (APE-413). patch, insert and edit results carry context computed from the exact bytes written (planned bytes for a dry run) by packages/core/src/edit/context.ts: the new digest, changed and inserted targets with their editable values, and removed targets. Unchanged components are omitted, and line moves alone do not count as a change. The delta lists at most 40 entries and cuts query text at 2000 characters, pointing to action:context when bounded; context:"full" and context:"none" are available. Verified by tests/unit/source-edit-transaction.test.ts (delta values, digest reuse, external-edit conflict, removed columns, modes).

    A03 working filters (APE-422). The addFilter edit operation (packages/core/src/edit/filter.ts) inserts the item and an optional container region, makes every target report, cards region or chart series submit the item (a missing property, a scalar list or an Oracle-exported [ ... ] array) and adds one refresh of all targets, in one page transaction. Optional complete replacement SQL is applied per report (with its column contract), cards region or chart series. Predicates are never rewritten: a target query that does not bind the item is refused (FILTER_NOT_BOUND), as are other region families. Verified:

    • Repository tests (tests/unit/source-edit-filter.test.ts): submitted items and binds of every target, array extension without reformatting, one refresh of all targets, unchanged existing dynamic actions, refusals and conflicts.
    • Local preview (SQLite) in the same test file: the filtered report shows all rows initially, only matching rows for a changed value, no rows for a value without matches, and all rows again after clearing.
    • Oracle offline compiler (SQLcl 26.3.0.260.1620, 26.2 profile) on a scratch customer-crm project: report filter on page 10, cards and chart-series filter on page 20, both passed with 0 diagnostics and 0 warnings (docs/evidence/fast-dev/addfilter-compiler-2026-11-25.json, local, not committed).
    • Not run: native import and browser behaviour on an APEX target.

    V08 one coherent source snapshot per refresh (APE-418). A refresh reads the .apx signatures once and passes that snapshot to change detection, loadApplication (file list and parse-cache keys, no second walk or per-file stat), affected pages and revision recording. One integrity recheck stays, for correctness: each file parsed in this load must still have the snapshot's signature. If it changed while it was read, the load is discarded, the last good renderer and its revision stay, and the next request scans again (the first load retries up to three times). The preview revision record (previewRevisionRecorder) now hashes only files whose size or modification time changed since the previous load, over the same files as sourceInventory, and records only when every loaded .apx file still matches the snapshot the load used, so it never claims a revision that was not rendered. This is a status record; plans, backups and imports keep reading fresh bytes. Full rescans on uncertain watcher events, the last-good renderer on parse errors, and distinct pending/error/rendered/validated/deployed states are unchanged. Verified by tests/unit/preview-review.test.ts (the incremental record equals the sourceInventory revision, a stale snapshot is not recorded, an edit landing mid-load keeps the last good page and is read on the next request) and tests/unit/preview-source-index.test.ts.

    V09 reused diagnostics and a shared theme index (APE-430). Each preview load now records phase timings (PreviewServer.loadTimings: parse, renderer construction, setup with the shared-component file check, property checks with pages checked and reused, lint, total).
