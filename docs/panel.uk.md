# Панель розробки

[English](panel.md) | Українська

Відкрийте `$apexrest-panel` у Codex для налаштувань проєкту й фактичного стану операцій Oracle/APEX. Скіл викликає `apexrest_panel_open` з абсолютним каталогом застосунку та відкриває повернену приватну локальну URL всередині Codex. Використовуйте проєкт застосунку з `apexrest.json`, а не джерела плагіна чи встановлений кеш. Відкриття або запуск панелі вимагає, щоб цей налаштований проєкт був у `trustedProjects` приватної політики; інакше операція завершується з `PROJECT_TRUST_REQUIRED`. Реалізація триває в [поточній розмові](chat-workflow.uk.md).

```sh
apexrest panel tui --project /absolute/application
apexrest panel status --project /absolute/application --json
apexrest panel open --project /absolute/application --json
```

## Подання

| Подання         | Вміст                                                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview        | Проєкт, зміни Git, фактичний транспорт Oracle та недавні операції                                                                                   |
| APEX operations | Фонові завдання, фактичні вкладені результати, діагностика, артефакти й збережений стан розгортання; компіляція, тести та плани з явним середовищем |
| Settings        | Ідентичність проєкту/середовища, toolchain, обов’язкові набори, браузер перевірки, SQLcl CLI/MCP та Direct Oracle listener / ORDS HTTP(S)           |

Консоль використовує той самий знімок. Обирайте подання цифрами чи стрілками, прокручуйте стрілками вгору/вниз або клавішами сторінок, оновлюйте через `r`, виходьте через `q`. Вебподання оновлюється, поки видиме, і зберігає фокус полів. Зміни транспорту бази стосуються майбутніх операцій; не змінюйте його під час роботи з базою. Історія завдань і розгортань показує найновіші 2000 записів кожного виду й повідомляє, скільки старіших записів пропущено. Знімки `panel.status` не архівуються як артефакти результатів; їхній повний вміст передається в інтерфейс панелі.

## З’єднання й браузер

Прямий доступ Oracle обирає наявне saved connection SQLcl. Відкриття налаштувань завантажує локальні збережені назви без входу в базу; оновлюйте список явно. Наявні відповідності зберігаються за порожнього списку чи зміни транспорту.

ORDS використовує URL схеми та ім’я/пароль наявного облікового запису бази. Вводьте дані лише в приватній локальній панелі або через CLI `--password-file`. MCP-дії з’єднань не приймають паролів. Прямі й ORDS-відповідності зберігаються окремо. Дивіться [налаштування ORDS](ords.uk.md).

`browserMode: codex|external` обирає браузер перевірки сторінок APEX; панель розробки залишається в Codex. Відкриття браузера не є перевіркою поведінки.

## Дії та захист

`apexrest_panel_action` приймає дозволені дії: `preferences`, `connection`, `saved-connections`, `cancel-job`, `validate`, `test`, `browser`, `plan`. Глобальні налаштування SQLcl, зокрема рівень обмеження MCP, недоступні моделі: змінюйте їх в автентифікованій локальній панелі або командою `apexrest sqlcl configure`. Вид дії `sqlcl` не приймається через MCP чи CLI `panel action`. CLI `--action` має бути одним JSON-об’єктом; некоректний JSON завершує команду з кодом 2.

```sh
apexrest panel action --project /absolute/application --action '{"kind":"validate"}' --json
```

Панель не надає довіру проєкту чи дозвіл розгортання й не застосовує план безпосередньо. Імпорти використовують [процес розгортання](deployment-safety.uk.md). Фактична помилка завдання лишається помилкою після нормального завершення процесу: статус завдання показує власний результат операції `failed`, `outcome_unknown` або `cancelled`. Завдання, worker якого так і не запустився, має стан `failed`, а не невідомий, і після усунення причини потребує нового завдання. Якщо завдання завершилося, але його записаний результат неможливо прочитати, MCP повідомляє `completed_unreadable`; огляньте наявний запис замість повторення операції. Втрачений heartbeat або відповідь зміни можуть залишити `outcome_unknown`; з’ясуйте результат перед повтором. Скасування не відкочує попередніх змін.

Сервер прив’язаний до loopback, перевіряє Host/Origin, видає лише дозволені ресурси й потребує приватного ключа для даних/дій. URL з ключем і файл сесії мають залишатися приватними. Спільне ядро зберігає перевірки довіри, ідентичності цілі, дозволу, backup і drift.

[Історичні локальні докази 1.0.0](evidence/current-session-100-local.json) фіксують перевірки панелі тієї редакції; [докази каталогу](evidence/component-catalog-local.json) — доповнення 1.1.0. Попередні звіти панелі/браузера зберігають початкові межі та не є скріншотами чи доказом відображення цього інтерфейсу.
