# Програмна автоматизація для Codex

[English](codex-automation.md) | Українська

Плагін призначений для Codex desktop і CLI. Його [19 обробників MCP](../packages/core/src/operations.ts) виконують звичайний програмний код; механічні кроки компіляції, читання метаданих, тестів і розгортання не потребують моделі. Codex забезпечує розуміння завдання, зміни джерел та оцінку в поточній розмові.

## Що працює без ШІ

У назвах нижче пропущено MCP-префікс `apexrest_`. Програмне виконання також потребує відповідного дозволу на зміни.

| Інструменти                                     | Програмна відповідальність                                                                                    | Внесок Codex                                                                |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `doctor`, `project_inspect`                     | Перевірити можливості й конфігурацію проєкту; за потреби обчислити хеші джерел                                | Пояснити відсутні передумови й вибрати потрібний контекст                   |
| `metadata_read`                                 | Перевірити межі й ціль, виконати дозволені запити з пагінацією                                                | Вибрати об’єкти й зрозуміти їхній бізнес-зміст                              |
| `reference_search`, `reference_read`            | Ранжувати, кешувати, ділити на сторінки й читати зафіксовану довідку                                          | Вибрати відповідний синтаксис і рішення проєктування                        |
| `apex_generate`, `apex_export`, `apex_validate` | Виконати генерацію Oracle, експорт у staging і перевірку компілятором                                         | Визначити застосунок і виправити джерела за діагностикою                    |
| `deploy_plan`, `deploy_apply`                   | Створити незмінний план; забезпечити ідентичність, дозволи, резервування, drift, lease і перевірку результату | Пояснити зміну й діяти в межах наданого користувачем дозволу                |
| `test_run`                                      | Виконати налаштовані набори перевірок і зібрати фактичні докази                                               | Вибрати доречні перевірки, написати твердження й оцінити покриття           |
| `job_status`, `job_cancel`, `artifact_read`     | Очікувати, відстежувати скасування й читати обмежені очищені артефакти                                        | Зрозуміти результат; з’ясувати невідомий результат перед повторенням запису |
| `browser_open`                                  | Визначити налаштовані URL і передачу керування браузеру                                                       | Використати доступні засоби браузера Codex і оцінити видиму поведінку       |
| `panel_open`, `panel_status`, `panel_action`    | Надати локальний UI, зібрати стан і виконати перевірені дії                                                   | Обрати потрібну операцію Oracle/APEX або зміну налаштувань                  |

Жоден обробник не потребує додаткової моделі лише для форматування звіту, опитування worker, переліку файлів чи пошуку точної довідки. Розуміння предметної області, проєктування застосунку, нетривіальні зміни й змістовне рев’ю все ще потребують міркування Codex. Успішні програмні перевірки не доводять відповідності застосунку потребам користувача.

## Реалізоване скорочення звернень до моделі

- Шість тривалих MCP-інструментів (`apex_generate`, `apex_export`, `apex_validate`, `deploy_plan`, `deploy_apply`, `test_run`) запускають завдання один раз і очікують у тому самому виклику. `waitSeconds` приймає 0–30, типове значення — 25. Після завершення повертається наявне завдання з вкладеним результатом, а фактичний результат також відображається у зовнішніх `ok`, `status`, `exitCode` і MCP `isError`; після timeout — той самий `jobId` для `job_status`. Значення 0 дає негайне підтвердження. Скасування очікування MCP не скасовує саме завдання; явне скасування завдання зберігає чинні запобіжники.
- `metadata_read` приймає наявний одиничний запит або `requests` із 1–8 запитів. Усі запити перевіряються до SQL; пакет один раз перевіряє ціль, потім послідовно виконує запити в дозволених межах. Кожен запит зберігає пагінацію й позначку недовіреного вмісту. Некоректний пакет не перетворюється на частковий успіх.
- `project_inspect` приймає `detail: "summary"` для шляхів проєкту й налаштувань середовища; повна перевірка лишається типовою. Підсумок не читає джерела застосунку й не звертається до Oracle. Налаштовані значення цілі не є перевіреною ідентичністю цілі.
- Обмежений MCP-вивід зберігає придатну для дій вкладену діагностику помилок, ідентифікатори артефактів і відомості про безпеку плану розгортання; повний очищений результат доступний через читання артефактів.

## Поточні докази та межі

[Історичні докази 1.0.0](evidence/current-session-100-local.json) фіксують його каталог інструментів і перевірки; [докази каталогу 1.1.0](evidence/component-catalog-local.json) — новий корпус компонентів. [Попереднє вимірювання автоматизації](evidence/codex-automation-runtime.json) зберігає початкову версію: підсумок синтетичного проєкту з 50 файлами мав 659 байтів UTF-8 проти 4,494 для повної перевірки. Це історичні дані розміру відповіді, а не поточний облік токенів хоста.

Робота починається безпосередньо в розмові Codex без виклику реєстрації плагіна. Завантажуйте лише потрібні skills/довідку, повторно використовуйте підсумки й наявні ID завдань, відкривайте панель за потреби. Codex керує моделями й співпрацею. APEXREST керує відновлюваним станом операцій без дублювання контексту розмови.

Ці зміни зберігають дозвіл, ідентичність цілі, backup, drift, координацію, обов’язкові набори й відновлення невідомих результатів. Локальна кількість викликів і вимірювання UTF-8 не доводять наскрізної затримки нативного хоста, економії оплачуваних токенів або коректності живого Oracle. Для цього потрібні окремо записані зіставні завдання хоста й дозволені підключені перевірки.
