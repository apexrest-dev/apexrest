    The source inventory was checked on 2026-10-11 and refreshed on 2026-10-14 and 2026-10-15 using web discovery, GitHub repository and code search, live GitHub recursive trees, immutable source archives and license text. It covers Oracle APEXlang .apx sources. Source counts describe files and applications, not independently verified ready components.

    Scope and verification

    • Oracle APEX 26.2 contributes 33 complete source applications, 2,961 .apx files and 1,506 page files at one pinned commit. The page reference intake selects 1,350 page files with page numbers greater than 0 and less than 9999. This numerical filter excludes global pages and high-numbered pages; it does not by itself identify every login, administration or scaffolding page.
    • The Oracle skills repository contains 456 .apx files across its 26.1 and 26.2 example applications and scaffold. Its three 26.2 example applications contain 242 .apx files, including 94 page files. Versioned copies and scaffold duplicates are not additional unique templates.
    • Seventeen licensed community candidates were inspected separately: seven on 2026-10-11 and ten more on 2026-10-14. They are discovery candidates, not automatically accepted ready recipes. Parser fixtures, intentional fault laboratories, duplicated vendor scaffolds and unlicensed sources are not treated as ready components.
    • Public source inspection confirms file identity, declared metadata and license. It does not confirm Oracle compilation, schema availability, an error-free server import or browser behavior. A copied page often depends on the rest of its original application.

    The Oracle page intake is a reference corpus. A recipe becomes ready only after its dependency closure, adaptation contract and required compiler checks are recorded in the recipe registry. Catalog inclusion must retain this distinction.

    Dependencies and adaptation

    The full application payloads total 49,883,949 uncompressed bytes. Many examples use EBA_DEMO_* tables, supporting SQL packages, shared LOVs, breadcrumbs, authorization schemes, plug-ins, static files or external REST endpoints. Charts, reports and maps may require database features or seeded sample data. Some sample pages perform writes, reset sample data, or change authentication behavior. Source inclusion is not authorization to run those actions or install supporting objects.

    For a reusable recipe: preserve provenance and license; choose the actual component rather than a navigation-only sample page; resolve shared references; replace sample-schema SQL with a documented synthetic projection or explicit project data contract; preserve the destination authentication; and run the required Oracle compiler checks. Import and browser evidence remain separate. Do not remove source-declared MMD requirements or silently claim 26.1 compatibility for 26.2 examples.

    A useful dependency-light extraction candidate is Dynamic Actions: Debounce and Throttle. Its interaction is client-side, but breadcrumb and authorization references still require adaptation. Most richer reporting, card and chart examples require their source data contract.
