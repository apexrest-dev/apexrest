# Налаштування публікації

[English](publishing.md) | Українська

Користувач вибрав [apexrest-dev/apexrest-codex](https://github.com/apexrest-dev/apexrest-codex) репозиторієм коду. Git origin і `publisher.config.json.githubRepository` використовують його. Коміти, push до `main` й публікацію `apexrest@1.2.0` у npm явно дозволено. `apexrest@1.2.0` опубліковано як npm `latest`; цілісність пакета в реєстрі та чисті локальне й глобальне встановлення підтверджено в [записі публікації](evidence/npm-120-publication.json). Публікація npm — окремий процес від захищеного publisher артефактів GitHub, який залишається вимкненим. [Запис попередньої публікації 1.1.0](evidence/npm-110-publication.json) зберігає докази цілісності в реєстрі та чистих локального й глобального встановлень. Цей дозвіл не вмикає GitHub releases, теги, розгортання сайту чи зміни DNS/TLS.

Перед увімкненням захищеного publisher артефактів GitHub власник має створити захищене release environment і зовнішньо керований ключ підпису, перевірити ліцензії Node/Java/SQLcl/браузера, виконати справжні тести нативного хоста для кожної платформи та завершити докази Oracle/utPLSQL/CRUD для точного незмінного коміту. Налаштуйте GitHub private vulnerability reporting і перевірений контакт безпеки. Процес npm потребує перевіреного володіння `apexrest`, чинних перевірок пакета, цілісності архіву та доказів чистого встановлення; він не закриває окремі умови кваліфікації підписаних артефактів.

`npm run release:dry-run` перезбирає плагін і сайт із поточного дерева, потім записує відтворювані локальні ZIP, контрольні суми, CycloneDX SBOM, походження, точні локальні команди встановлення та release-readiness.json. Для непідписаних локальних артефактів він приймає незакомічені зміни. `npm run release:package`, який використовує процес випуску, відмовляється пакувати робоче дерево зі змінами або нечитабельне дерево й зупиняється, якщо код змінився під час збирання. Платформно-незалежне середовище виконання постачається одним архівом `apexrest-runtime-<version>.zip` замість однакових копій для кожної платформи. Повідомлення сторонніх пакетів охоплюють лише production-залежності, що поширюються в пакеті, а не засоби розробки. Збірки з незакоміченими змінами/без коміту мають digest дерева коду й не можуть бути стабільними. Manifest можна підписати лише явно наданим зовнішнім `APEXREST_RELEASE_SIGNING_KEY_FILE`. Перевірка bootstrap публічним ключем необов’язкова для локально вибраного користувачем SHA; майбутній віддалений канал має вимагати довірений підпис. Непідписані локальні бета-файли не подаються як опубліковані випуски.

Захищений процес випуску ручний і використовує protected environment. Stable readiness блокує випуск за відсутніх, застарілих або отриманих з іншого коду обов’язкових доказів. Конфігурацію publisher також слід увімкнути. Копіюйте лише `site-dist/` під наявний шлях `/codex/` через `scripts/publish-site.sh --dry-run DEST`; фактичне копіювання потребує явного `--apply` та змонтованого дозволеного місця призначення. Не змінюйте кореневої головної сторінки. GitHub-артефакти залишаються незмінним джерелом; інсталятори/метадані сайту генеруються з того самого release manifest.

Подання в каталог OpenAI — окремий ручний процес. Підготуйте ідентичність/автора, ліцензію, обробку даних, підтримку й докази нативної сумісності. Прийняття в публічний каталог не гарантоване й не потрібне для локального нативного встановлення.
