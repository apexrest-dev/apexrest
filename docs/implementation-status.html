    Compound edits and recipes, Slice F (2026-11-22, local, uncommitted)

    Page context (APE-381). project context (CLI) or apexrest_project action:context returns, for one page:

    • the page file and its digest, which is what patch binds to;
    • every region with its type, title and sequence, and for reports also the SQL and the columns (heading, format, sequence);
    • the items and buttons, each as a ready target.

    An agent no longer needs to read the page file.

    Report SQL with its columns (APE-371, APE-367). The query patch operation replaces an interactive or classic report's fenced SQL and sets its complete column contract in one change:

    • kept columns keep every property and id (an optional heading replaces theirs);
    • dropped columns are removed;
    • new columns get a heading, a data type and the next sequence.

    It refuses columns the query does not name, and non-report regions. Verified on the local APEX 26.2.0: CREATED_AT ("Created") was added to the customers report with its SQL through context and patch, then shipped.

    Agent routing (APE-384). The work skill sends titles, labels, headings, formats, sequence and report SQL/columns to action:context then patch, and the patch reference documents query.

    Dashboard recipe (APE-380). The existing scaffold already generates a filtered dashboard: cards, a line chart, a select-list filter and the refresh dynamic action. Verified on the local APEX 26.2.0 (3 regions, 1 item, 1 dynamic action).

    Bug found: an explicit lower-case page alias was emitted unchanged, and the compiler rejected it (VALUE_NOT_UPPERCASE). Aliases are now upper-cased, with a test.

    Not done in this slice:

    • inserting regions or filters into existing pages (APE-369, APE-370);
    • shared Composer and scaffold contracts (APE-357);
    • the modal form (APE-376), interactive grid (APE-383), master–detail (APE-391) and faceted search (APE-393) recipes, which need new scaffold region types.

    Warm state and session qualification, Slice E (2026-11-22, local, uncommitted)

    Where import time goes. On the local APEX 26.2.0 target, a page import spends 2.5 s on the fresh pre-write export, 0.65 s connecting and 3.1 s in Oracle's import. The prepared import server's JVM is already started off the critical path (spawn 0 ms). Each database script costs about 1.7–1.9 s in its own SQLcl process.

    JVM and compiler reuse (APE-382, APE-388). Not kept across imports: there is no measurable gain, and a server is bound to one frozen import directory. The fallback rules now have tests: a server without the HOST refusal, or one that fails to connect, submits nothing and falls back; after submission a failure or cancellation is reported as an interrupted import; the server runs one import only.

    Connected-session reuse (APE-386, APE-390). scripts/bench/session-reuse.mjs was run on SQLcl 26.3 and Oracle 23.26.4; the evidence is in docs/evidence/fast-dev/session-reuse-2026-11-22.json.

    • Without a reset, the next operation sees the earlier one's uncommitted row, its package global (42) and current_schema=SYS.
    • ROLLBACK, package reinitialization and a current_schema reset clear all three.
    • WHENEVER SQLERROR EXIT ends the session before the marker (exit 2) and rolls back.
    • Process exit commits pending DML.

    One session for an apply's scripts (APE-404). Implemented as ScriptSession, used when an apply has two or more scripts.

    Server-mode qualification on SQLcl 26.3:

    • HOST is refused;
    • each script with its marker is committed;
    • an error leaves no marker and rolls back; the server stays alive but its connection is dropped;
    • a killed process mid-script returns "Connection closed" and the work is rolled back.

    On the local APEX 26.2 target, two package scripts took 2.03 and 2.13 s against 3.91 and 3.98 s with one process per script (alternating, 2 runs each); the objects stayed VALID. In a failure run the first two scripts recorded as applied after their markers. The third failed (ORA-01476) and the run became OUTCOME_UNKNOWN (ORACLE_COMMAND_FAILED), the same classification as the process path. It was released through deploy reconcile. Unit tests cover the fallback, reset, discard and failure rules.

    Reviewed database reconciliation (2026-11-22, local, uncommitted)

    APE-403. apexrest deploy reconcile releases a run held as database-review-required once a person has inspected the database:

    • the person states every migration and package of the run as applied or not_applied;
    • the person types --confirm <run id>:<plan digest prefix>;
    • the command records userRequest and the statement in reconciliation.json, updates the local history exactly as stated, and releases the run's ownership.

    It never connects to the database. It refuses an incomplete statement, a different environment or target, production, a finished run, another host and a live run process. It is CLI only, with no MCP tool.

    Database-only plans and aliases. importMode:none plans no longer fail on another workspace application's alias (APPLICATION_ALIAS_IN_USE); they import no application.

    Development broker, Slice D (2026-11-22, local, uncommitted)

    Broker (APE-361, APE-373). broker.ts adds apexrest dev start|status|stop: one process per project on a private token-protected Unix socket or named pipe. It has an idle timeout, and its stop waits for running jobs. Ship apply jobs from MCP go to the broker when it runs; otherwise they use the detached worker as before.

    Ownership (APE-365). Every runner (broker, detached worker, in-process) now claims a job with claim.json, created with O_EXCL, before it runs. An unconfirmed hand-off can therefore start a fallback worker without running the job twice. failQueuedJob no longer fails a claimed job; its heartbeat decides. Never-started, started-unknown and completed-with-lost-response jobs keep their existing records.

    Coalescing (APE-375). The broker runs ship.apply jobs one at a time per environment. Waiting jobs collapse into the newest when its plan is at least as recent. The others become superseded (shown as a success that never started, naming the job that applies the changes). A running import is never touched.

    Unknown outcomes (APE-372). Already enforced: an unknown outcome keeps the deployment lease (TARGET_LOCKED), as seen with the held local run 08e6e532.

    Measured (APE-378). On the local APEX 26.2.0 target, ship.apply jobs measured from start to terminal state, 3 runs each, alternating:

    Runner Median Backup Import
    Detached worker 9.31 s 2.11 s 6.52 s
    Broker 9.06 s 1.99 s 6.49 s

    The broker saves about 0.25 s, within run-to-run noise. The import itself dominates, through the isolated SQLcl write session. A coalescing check on the same target queued two applies back to back: the first was superseded and the second completed.

    Incremental preview, Slice C (2026-11-22, local, uncommitted)

    Source index (APE-351). loadApplication takes a per-file parse cache keyed by size, modification time and substitutions, so unchanged files keep their parsed components. preview/source-index.ts lists the changed files and the affected pages:

    • a page file affects that page;
    • a shared component affects the pages that reference it;
    • the application, the global page, a theme or an unknown file affects every page.

    Watcher and stale state (APE-353, APE-359). Watcher events mark the sources dirty before the debounce. Requests rescan only when the sources are dirty, when no watcher is running, or every two seconds. A failed load keeps the last good renderer with a "Stale preview" banner and the error. Previously every page returned HTTP 500.

    Targeted reload (APE-358, APE-366). Reload messages carry the source revision, the files and the affected pages; hello carries the revision, and older or repeated notifications are ignored. CSS static files are replaced in place.

    Region replacement (APE-374, APE-368). An in-place edit that changes only static content, classic report, interactive report or cards regions is replaced through the regions' existing refresh lifecycle. Everything else reloads the page.

    Text edits in those regions are covered by the region replacement. Item and button labels reload the page; there is no separate text patching.

    Verified:

    • Unit tests cover equivalence of cached and clean loads, scope, renames, stale state, region eligibility and the live message.
    • In the built-in browser with two tabs, patching the region title on page 10 replaced that region in place: the tab was not reloaded and the new text appeared. The page 1 tab was not touched.

    Semantic page edits, Slice B (2026-11-22, local, uncommitted)

    Lossless editor (APE-350). edit/apexlang-edit.ts scans one .apx file into components, groups and property lines with exact offsets. ``` literals, object and array values, and // and /* */ comments stay opaque. An edit replaces only a property's value bytes. A missing property or group is inserted with the file's indentation and line ending. Values that would read as references, booleans or quoted text are written as JSON-quoted text. The preview parser only validates the result.

    Results:

    • Over the repository corpus, the scanner accepts all 1,353 .apx files.
    • Setting 68,243 scalar properties to their current value changed 0 bytes.

    Committed source revision (APE-356). edit/patch.ts binds an edit to the digest of the page file the caller read. It checks the digest again under .apexrest/source-edit.lock right before an atomic replace, and returns the before and after digests and the SourceChange (files and affected pages). Without the digest, or with dryRun, it returns currentDigest and writes nothing. Stale, repeated, ambiguous, unsupported and overlapping requests fail before any write. A patch only edits one page file, so there is no multi-file staging.

    Operations (APE-364, APE-362, APE-363):

    • page title;
    • region title (name) and sequence;
    • item label (label.label) and sequence;
    • button label and sequence;
    • column heading (heading.heading), format (appearance.formatMask) and sequence.

    Route (APE-360). The CLI command apexrest project patch and MCP apexrest_project action:patch share one path. The composite MCP schema is loose; the granular operation validates strictly. The MCP catalog budget was raised to 15,500 bytes for this action. The skill reference (references/patch.md) and docs/apex-26.2.md document it.

    Verified:

    • Unit tests cover CRLF, non-ASCII text, quotes, fences, comments, insertion, conflicts, ambiguity, a stale digest, the MCP route and the CLI route.
    • On the local APEX 26.2.0 (application 26220), one patch changed a region title, a column heading and a column format mask. The diff was 5 lines added and 2 removed, then ship imported it. The APEX dictionary shows Customer list, Email and UPPER.
