# Стан реалізації

[English](implementation-status.md) | Українська

## Composer — локальна реалізація, 2026-09-29

Кандидат `1.3.0-beta.1` містить робоче локальне ядро Composer, шість experimental renderers, два blueprints, CLI/MCP та Catalog. Аудит **не підтверджує** завершення CMP-000–041: shared-resource ownership, повна compatibility/evidence policy, нормалізація довільного captured source та частина матриці перевірок залишаються незавершеними. [Аудит](composer/audit.uk.md), [ledger](composer/ledger.json) та [evidence](evidence/composer-local.json) відділяють реалізовану поведінку від залишку роботи. G4, live SQL/import/roles/browser, завантаження в новому чаті та нові Linux/Windows CI results залишаються відкритими. Published 1.2.0 evidence нижче є історичним.

Повторний огляд додав регресійні перевірки детермінованості вкладених mappings, переходів page ownership, exact API bindings, повноти journal та retry/invalidation панелі. Поточні результати тестів і встановлення зафіксовані в Composer evidence; ця перевірка не змінює відкриті roadmap і runtime gates.

Для кандидата бета-версії локально пройшли 262 unit-тести, 59 contract-тестів, 26 installer-тестів і 25 packaging-тестів, а також lint, typecheck, двомовна документація, Composer catalog/verification, синхронізація native bundle та CLI/stdio MCP smoke-перевірка архіву. Release dry run показав `stableReady: false`, оскільки перевірки Composer, Oracle й нативного хоста залишаються відкритими. Публікацію в реєстрі ще не підтверджено.

## Реалізація робочої копії — 2026-09-29, кандидат бета-версії

Checkout додає `apex.sync`, CLI `apex sync --env NAME --action init|status|refresh|invalidate`, дев’ятнадцятий MCP-інструмент `apexrest_apex_sync`, явне перенесення working copy, локальне джерело diff та стан у панелі. [Процес наявного застосунку](existing-app.uk.md) описує одного редактора. Наведені нижче докази опублікованого 1.2.0 залишаються історичними доказами розповсюдження; публікацію кандидата в реєстрі ще не підтверджено. Поточне локальне встановлення відстежує Composer evidence.

Реалізовано: приватний атомарний стан sync та журнал переходів; незмінний APEXlang baseline/SQL-копія; читання метаданих; прив’язані v2 плани; повний імпорт зафіксованих локальних джерел без повторних експортів; перевірки ревізії/локальних змін/security/невідомих результатів; сумісність із v1/повним експортом та окремим відновленням baseline. Чистий refresh зберігає попередні артефакти й замінює відому чисту робочу копію. Звичайні status/панель не викликають Oracle. Активне сховище захищене від очищення результатів.

Локально перевірено: справжній код sync/plan/apply з імітованими межами Oracle/compiler/tests, transport fixtures для метаданих direct SQLcl/ORDS, перезапуск та відповідність CLI/stdio MCP. [Звіт вимірювання](evidence/working-copy-local.json) відділяє початкові 1 APEXlang + 1 SQL експорт від трьох наступних імпортів без експортів проти 9 + 3 експортів за три старі цикли. Час і байти відповіді виміряні локальним harness; це не latency Oracle, tokenizer чи billing-докази. [Звіт перевірок](evidence/working-copy-checks.json) окремо фіксує поточні build/typecheck/lint/unit/contracts/packaging/docs/plugin перевірки.

Oracle-перевірок цієї зміни немає. Connected initial sync + три зміни з перезапуском, справжні імпорти, автентифікований браузер застосунку та окреме SQL-відновлення baseline — NOT RUN; live qualification є окремо погодженим етапом. Composer Catalog перевірено у браузері Codex; installed payload та завантаження tools у новому чаті перевіряються окремо. Обсяг наявних required suites збережено. Plugin-owned агентів, команд і model router не додано.

## Поточний обсяг — 1.2.0, 2026-09-24

APEXREST працює безпосередньо в поточній розмові Codex. Опублікований 1.2.0 надає 18 MCP-інструментів з обмеженим виводом, 13 спеціалізованих skills, CLI та необов’язкову панель операцій і налаштувань Oracle/APEX. Skill наповнення каталогу патернів розширює процес роботи з каталогом без нового MCP-інструмента. Codex керує завданням, контекстом, моделлю, дозволами й власною співпрацею. Виклик запуску роботи плагіна, контролер сесій моделей, маршрутизація ролей і вибір моделей не входять до продукту.

Випуск зберігає генерацію/експорт/валідацію APEXlang, пошук зафіксованої довідки, обмежені пакети метаданих, транспорти SQLcl CLI/MCP та ORDS, план/застосування розгортання, налаштовані тести, відкриття браузера, стійкі завдання й обмежене читання артефактів. Панель зберігає налаштування проєкту/з’єднань і браузера перевірки.

Розгортання й надалі потребує фактичної ідентичності цілі, дозволу, перевірок drift джерел/цілі, координації та перевіреного backup наявного застосунку. Невідомі результати запису потребують з’ясування. Обов’язкові набори не можуть пройти з порожніми, пропущеними чи заблокованими результатами. Production потребує захищеного зовнішнього схвалення.

## Каталог патернів

Окремий [каталог патернів](pattern-catalog.uk.md) додає офлайн-пошук `corpus: "patterns"` та ID `pattern:` для готових композицій сторінок. `$apexrest-pattern-catalog` приватно захоплює структурні факти й керує повним оглядом сторінок та варіантів і підготовкою власних рецептів. Сталі ID джерел зберігають інші джерела; заміна потребує перевіреного оновлення. Registry `sourceReviews` прив’язує кожне рішення щодо сторінки до її точного хешу джерела. Builder відхиляє відсутні чи застарілі огляди, невідомі source anchors і патерни, не згадані в оглядах сторінок. Покриття доступне через `pattern:source/<sourceId>/review` та `/review/page-<id>`.

[Universal Theme Reference](https://apex.oracle.com/ut) та Oracle APEX UX Pattern Catalog перевірено й експортовано лише читанням. [Manifest патернів](../resources/patterns/manifest.json) фіксує два джерела, 150 сторінок (122 + 28), 818 перевірених варіантів, 58 патернів і 84 рецепти: 69 власних реалізацій та 15 явних unresolved-записів. Усі 69 реалізованих рецептів пройшли реальну офлайн-валідацію SQLcl без попереджень: зведена перевірка охоплює 56 доповнень разом із 13 наявними підтвердженнями. [Локальний запис доказів](evidence/pattern-catalog-local.json) відокремлює фактичні перевірки каталогу/збірки/пакета від доказів компіляції рецептів.

Digest UX-експорту та хеші всіх 147 раніше захоплених файлів джерел Universal Theme не змінилися. Нове захоплення також інвентаризує 53 binary/static resources як факти без їхнього поширення. Виправлення reader зберігають 15 раніше пропущених анонімних декларацій UX-джерела (1099 об’єктів, 102 shared components) та сім анонімних branches Universal Theme; більший інвентар не є доказом змін у застосунках-джерелах. Форми джерела не доводять бізнес-DML, необов’язкові fixtures не встановлювалися, AI-провайдер лишається неналаштованим. Власні рецепти навігації та вибору/оновлення не копіюють JavaScript джерел. Порожні концепції й непідтримана поведінка залишаються unresolved.

Докази рецептів прив’язані до повних вхідних файлів scaffold та overlay. Виконання SQL, імпорт застосунку й браузерна перевірка для цієї роботи з каталогом не виконувалися. [Матриця приймання](acceptance.json) відстежує реалізацію 1.2.0 окремо від доказів попередніх випусків.

## Перевірки

[Поточні локальні докази](evidence/pattern-catalog-local.json) фіксують 187 модульних тестів, 57 контрактних тестів, 26 тестів інсталяторів і 25 пакувальних тестів. Перевірки каталогів, документації, синхронізації плагіна та офлайн CLI/MCP після перенесення пройшли успішно. Усі 69 готових рецептів патернів зберігають докази реальної офлайн-компіляції SQLcl без попереджень. Публікація, чисті встановлення з реєстру й оновлення встановленого кешу є окремими перевірками.

Незмінений [каталог компонентів](component-catalog.uk.md), доданий у 1.1.0, надає офлайн-пошук серед 109 сімейств і 138 перевірених компілятором рецептів зі знімка Universal Theme 26.1 Reference, отриманого лише читанням. Один непідтриманий рецепт має явний статус unresolved. [Докази каталогу](evidence/component-catalog-local.json) фіксують покриття джерел, параметри з контекстом, справжній вивід офлайн-компілятора, 181 модульний тест, 42 контрактні тести й 19 пакувальних тестів. Кожен готовий рецепт прив’язаний до hashes scaffold і власних файлів; виконання SQL, імпорт і браузерна перевірка лишаються окремими й у цій роботі не виконувалися.

[Історичні локальні докази 1.0.0](evidence/current-session-100-local.json) фіксують точні джерела/збірку та перевірки, виконані для 1.0.0. CLI/stdio MCP, модульні, пакувальні й UI-fixtures підтверджують зазначену локальну поведінку; вони не доводять реальне міркування Codex, виконання Oracle чи відображення desktop, якщо запис явно не містить таких спостережень.

[Історичні підключені докази](evidence/ords-connected.json) підтверджують один дозволений незмінений цикл APEXlang export/import/export з 21 побайтово ідентичним файлом і SQL backup з перевіреною контрольною сумою. Попередні звіти нативного встановлення й компілятора шаблонів Oracle зберігають початкові версії та межі. Випуск каталогу не повторює тих підключених операцій і не розширює їхніх тверджень.

[Матриця приймання](acceptance.json) розрізняє поточні критерії, вилучені вимоги, наявні докази та відкриті перевірки. Початкова [специфікація збірки](../APEXREST_CODEX_PLUGIN_BUILD_SPEC.md) залишається незмінною як історичні вхідні дані. Історичні JSON-звіти збережено для походження доказів, включно зі звітами видалених функцій; вони не описують 1.2.0.

## Розповсюдження та відкриті перевірки

`apexrest@1.2.0` опубліковано як npm `latest`. [Запис публікації 1.2.0](evidence/npm-120-publication.json) підтверджує цілісність пакета в реєстрі та чисті локальне й глобальне встановлення для коміту джерел `858b5d14b45370fc2ba01d63013d636f1fa11070`. [CI випуску](https://github.com/apexrest-dev/apexrest-codex/actions/runs/36017573027) успішно завершився на Ubuntu, macOS і Windows. [Запис попередньої публікації 1.1.0](evidence/npm-110-publication.json) та [історичний запис публікації 1.0.0](evidence/npm-100-publication.json) зберігають перевірену цілісність, чисті встановлення й результати платформного CI.

Версія пакета й нативного плагіна — `1.2.0`. Ця публікація не заявляє оновлення кешу встановленого плагіна. Публікація npm відокремлена від вимкненого захищеного publisher артефактів GitHub. [Примітки до випуску](release-notes.uk.md) відстежують розповсюдження окремо від реалізації та перевірок. Встановлення з реєстру, локальне пакування, джерела GitHub і опублікований сайт — окремі результати.

Ширше покриття платформ нативного хоста, змінені імпорти Oracle, SQL restore, реальні переривання/відновлення, utPLSQL та автентифіковані перевірки застосунку лишаються відкритими там, де їх не охоплюють наявні докази. Вимірювання UTF-8 не є вимірюванням оплачуваних токенів. Дивіться [наступні дії](next-actions.uk.md).
