The current source and bundled plugin version is **2.4.0**. The current contract is described in [architecture](architecture.md), [testing](testing.md) and the [acceptance matrix](acceptance.json).

- Optional project-scoped OpenAI Decisions component selection through `apexrest_reference mode:select` / `docs select`: one bounded batch, compatible local shortlist, private ENV credentials and explicit local fallback. The current host model composes final APEXlang. Repository tests cover transport fixtures and CLI/MCP contracts; live fixed-case API selection, latency and usage are recorded below. Native-host application authoring remains separate.

- Six skills and eleven composite MCP tools for Codex and Claude Code, backed by one canonical work skill and CLI/runtime. Managed payloads include both marketplaces and bind both MCP adapters to the same Node executable and managed home; Claude retains cache-root expansion.
- Oracle SQLcl generation/validation, pinned release-specific references, blank/CRM templates and an experimental local Composer CLI.
- APEX 26.1 full imports and eligible APEX 26.2 selected-file imports through direct SQLcl CLI, with automatic scope selection, native selected-page export, scoped APEXlang backups/restore, exact plan binding, same-component conflict checks, scoped readback and durable checkpoints.
- Local durable migration history and schema coordination. Independent machines or managed homes require external serialization.
- Host in-app browser verification, separate from compiler and deployment completion. No automatic application test runners, saved browser-authentication state or browser-install steps. Dependencies are Node.js, Java and SQLcl.
- Private named connections, task-scoped grants without folder trust, redaction, bounded jobs/artifacts and recovery safeguards for unknown outcomes.
- Complete official 26.2 inventory: 389 definition documents, 130 declaration keywords and 32,187 contextual property occurrences, with full paginated MCP reads and the maintainer Oracle synchronization skill. New upstream release discovery is separate from pinned inventory currency; see [coverage](oracle-apexlang-coverage.md).
- Offline component, pattern, block and blueprint discovery. Recipe/compiler qualification belongs to the functional catalog and does not establish deployed application behavior.
- Public template intake: 1,350 checksum-bound APEXlang page references from 33 Oracle APEX 26.2 applications, with pinned UPL source attribution and application dependency inventories; `corpus:components`, `version:26.2`, `kind:template` retrieves them offline. Thirty additional dependency-closed 26.1 recipes cover dynamic actions, computations, validations, charts and template directives. [Source inventory](internet-template-sources.md) distinguishes public references from compiler-ready recipes and unimported community candidates; the 2026-10-14 refresh found no new Oracle source revision and added ten licensed 26.1 community candidates as discovery-only entries; two of them now have compiler-checked recipes.
- Repository [qualification harness](plugin-qualification-harness.md): profile/catalog selection, debug SQLcl statement and queue timings, metadata/concurrency/drift/resource/error cases, response budgets, environment-bound regression classification, saved-connection cost probes, Claude usage accounting and private native-host transcript metrics. The native task runner has deterministic checks for the selected read-only tasks; write/reset, operator, Composer and future P2/prewarm extensions remain incomplete.

- Current safety policy: DEV/QA/TEST deployment, production refusal, effective endpoint/server locality, operation-aware remote exact-plan risk confirmation and server-first APEX recovery without blind SQL replay.
- SQL review classifies database scripts and emits operation-specific risks; Composer predicate and extension scanners reject parenthesis-free routine calls, doubled-quote literal tricks and APEX dynamic-execution wrappers. SQLcl runs in its own process group with bounded output draining, and job records distinguish a worker that never started from an unknown outcome. POSIX escalation targets surviving descendants even after the launcher exits, a descendant that outlives a normal launcher exit is stopped at the drain deadline, and repeated stops are ignored with the pending SIGKILL cancelled once the group has closed; the script risk detection gap below remains open.
- Database-free [local preview](local-preview.md) (`apexrest preview`, `apexrest_preview`): APEXlang pages rendered with Universal Theme 26.2 templates and JavaScript extracted from the official distribution, the `wwv_flow.accept` submit protocol and SQLite data with Oracle SQL shims and on-demand sample tables. Feature modules add interactive reports and editable grids, faceted search, cards, template components, charts, calendars, maps, genuine item widgets, a PL/SQL subset interpreter and a wider dynamic action runtime; all pages of the three public Oracle example applications render without errors. Unit tests use a synthetic theme export; the real distribution was checked manually against the public Oracle example applications. On 2026-11-01 a generated 22-page showcase application covering reports, grids, forms, items, faceted search, cards, template components, charts, calendar, tree, map, wizard, files, dynamic actions and the PL/SQL interpreter exposed 34 preview defects. They were fixed in four groups — Oracle SQL semantics, transactional submit/runtime protocol, report/card/template rendering, and items/layout/maps with APEXlang property validation — with new unit tests (536 tests, 535 passed, one optional skip; lint and typecheck clean). The showcase then rendered with 0 errors and 0 warnings in `preview check`, and its key pages were inspected in the built-in browser without console errors. The 1,350 public Oracle sample pages produce no property-validation findings. It is a design aid, not compiler, import or Oracle evidence.
- Local ignored/untracked ENV credential input and browser checks only on user request; canonical rules are bundled from [deployment safety](deployment-safety.md).
